# agntc v2 design

Vercel parity was cancelled on 2026-10-12 because it grew to 15 phases. It's reopened narrower: agntc should install my own skills and anyone else's skill repos properly, so I can stop using `npx skills` entirely. This is a breaking major version. The design below was talked through on 2026-10-13 (sitrep sr-skhk3r) and is settled.

**Scope.** Claude only: the Codex and Cursor drivers, the agent prompt, `agents` in `agntc.json` and `.agents/skills` routing all go. flowx's two Codex entries get reinstalled for Claude only. Clone, semver constraints, nuke-and-reinstall update, grouped update, the manifest, the `list` dashboard and copy-safety stay as they are. The 0.x caret locking the minor is intended. Out of scope: Vercel's `@skill`/`#ref` grammar, naming installs by frontmatter, unattended and `--json` parity, extra git hosts, coexisting with Vercel installs, Claude Code plugin manifests, well-known endpoints, `find`.

**Vocabulary.** A **skill** is a folder with `SKILL.md`. Everything inside belongs to it, including its own `agents/` folder. A **pack** is a set of skills, optionally with agents and hooks, that installs, updates and removes as one entry. "Plugin" retires, because it clashes with Claude Code's own plugins. "Collection" retires too: a repo with several things in it just gives a menu. `--plugin` becomes `--pack`, and the old flag keeps working with a "renamed" note. Config `"type": "plugin"` and manifest `plugin` entries are read as packs.

**A pack is always declared**, never inferred from folder shape. The author declares it with `{"type": "pack"}` in that folder's `agntc.json`; the user declares it with `--pack`. Today's rule that `agents/` or `hooks/` makes a plugin goes, and so does forcing picked collection members into plugins. Agents and hooks install only as part of a pack, and only `.md` files from `agents/` become agents. When a folder's agents or hooks won't be installed, say so and print the `--pack` line that would install them.

**Finding skills.** Walk down from the path added (repo root or `owner/repo/path`, which is now accepted). A pack is recorded and not entered. A folder with `SKILL.md` is a skill and is not entered. Any other folder is descended into, up to 5 levels. Skip hidden folders, `node_modules`, `.git`, `dist`, `build` and `vendor`. Category folders are plain folders. Packs don't nest: a pack holds every skill found inside it plus its own `agents/` and `hooks/`. Everything installs flat as `.claude/skills/<folder>`. Identity stays the folder name. A name found twice shows in the menu with both paths, and `--skill` refuses it and lists the paths.

**Choosing.** One thing found installs without a menu. Several give a menu: one line per pack, loose skills shown by path. The menu never splits a pack. `--skill a b` matches the folder or frontmatter name anywhere, including inside a pack. A skill taken from a pack installs loose, with a note naming the pack and what's left out, and authors can't block that. `--pack` bundles the added path. It's refused on a single skill or on a path that contains packs, and does nothing extra on a path that's already a pack. `--pack` and `--skill` don't combine. A prompt that can't be shown because there's no terminal refuses the command and names the flags.

**Update.** A pack is one entry, keyed by path, and each update re-walks it, so additions arrive and removals go. A loose skill is one entry, keyed by name with its path recorded. If it moves, update follows it when exactly one skill has that name. If it's removed upstream, update asks whether to remove it. Yes deletes it; no keeps it at its last version and asks again next time. With no terminal, it's kept and reported. This isn't an error. A declared pack that disappears upstream gets the same prompt. Additions are never picked up for loose skills; that's what `--pack` is for. A pack absorbs loose entries from its own repo without prompting, and `--skill` on a skill already inside an installed pack does nothing and says so. Re-add commands agntc prints carry `--pack`.

**Global.** `-g` on `add`, `remove`, `update` and `list` roots the install at `~/.claude/`, with the manifest at `~/.agntc/manifest.json`. Update stays per scope. agntc must never write or delete through a symlink it finds in the destination.

**Agent use.** With no terminal, agntc never waits. Each question is either answered by a flag or the command stops, exits non-zero and names the flag:
- What to install: `--skill`, `--pack`, `--all` (everything the menu would list), or a path to one skill or pack.
- Replacing files in the way, whether another install's or files agntc didn't install: `--overwrite`. Without it, that item stops and the rest install.
- `remove`'s confirmation, and update's "gone upstream, remove it?": `-y`. Without it, `remove` refuses and update keeps the skill and reports it.

`--list` shows what a source holds without installing anything: packs with their skill counts, skills with their path and description. The description is a display-only frontmatter read.

Without a terminal, output is JSON on stdout and never clack: one document per command, with errors as JSON plus a non-zero exit. `--json` forces JSON at a terminal. Clack stays as the interactive surface for a person.

**Kit.** Kit's own skills in `~/.claude/skills` are kit's, and agntc never touches them. Kit sets up a new machine by running `npx agntc add -g …` lines, after which agntc owns those skills through `~/.agntc/manifest.json`. A name clash with a kit skill counts as files in the way, so an unattended run stops rather than replacing them.

**Before v2 ships:** add `"type": "pack"` to agentic-workflows' `agntc.json`, and to agentic-skills' `laravel/` and `nuxt/` (whose README line `add leeovery/agentic-skills/laravel` fails today).

**Fixed along the way:** skills carrying `agents/openai.yaml` were installed as plugins with their `SKILL.md` dropped; the stray `.claude/agents/openai.yaml` from avdlee in fumi; re-add advice dropping `--plugin`; a skill removed upstream aborting every update.

**Build order** (agreed 2026-10-13, built directly in a worktree on a v2 branch: an implementer agent per slice, each reviewed, tests kept green; no workflows):
1. Claude only: remove the Codex and Cursor drivers, the agent prompt, and `agents` in `agntc.json`.
2. Search and selection: skill and pack, `--skill`, `--pack` (with `--plugin` kept as an alias), `--all`, `--list`, `owner/repo/path`, the menu, no-terminal refusal, JSON output.
3. Update and safety rules: the removed-upstream prompt, following a moved skill, a pack absorbing loose skills from its own repo, re-add commands carrying `--pack`, `--overwrite` and `-y`, the duplicate-name guard, and the symlink guard (a link in the way is removed as a link; never write or delete through it).
4. `-g`.
5. Docs and wording: README, CLAUDE.md, `init` (scaffolds a skill or a pack), and "plugin" wording in `list`.
